# Cloudflare mapping and technical feasibility

Artifact: CF-FEASIBILITY-v2. **Proposed; no runtime verification or approval recorded.**
Original platform research: 2026-10-04. This retained assessment describes documented
support at that date; recheck details before implementation. Repository: `172x-data-intel`.

The active MVP is synthetic sales CSV through model-generated SQL in a general query
engine and support JSONL through targeted search, with native Cloudflare Agent chat,
durable memory, evidence, and independent validation. **Workers AI with Llama 3.3
is the MVP model baseline.** Runtime/engine compatibility and Llama 3.3 structured
output, tool behavior, analytical quality, and validation quality remain unverified
until tested. The demonstration uses **isolated anonymous sessions over bundled
synthetic datasets**. Server-owned session scope, protected secrets, safe SQL, and
per-session/global resource limits remain MVP requirements. Authenticated private
workspaces, login, OAuth, and enterprise tenancy are future work. Runtime/engine fit
still needs a spike. PostgreSQL, Parquet, uploads, whole-corpus classification, Workflows for long
jobs, Containers, and distributed execution are future options in this wider mapping.

## Verdict and authority

**CONDITIONALLY_FEASIBLE** for the bounded, evidence-first MVP. The dated research records Cloudflare support for native Python Workers, Python Durable Objects, Python Workflows, Python database drivers through Hyperdrive, durable execution, and Linux Containers. These are credible building blocks. Their availability does not establish that the selected packages, cross-language contracts, cancellation protocol, accuracy, cost, or large-data workload will meet this project's requirements.

Keep the data plane, reasoning roles, and durable execution boundaries. Use explicit engine capabilities and workload budgets to select an executor. The claim that the same implementation handles 20 MB, 20 GB, and 2 TB with equivalent behavior remains **unverified**. The same contracts can support different executors; that is an architectural inference, not measured capacity.

## Proposed platform mapping: MVP boundaries and future extensions

Every row is a proposed mapping, not an implemented feature. In the first MVP,
a native Agent persists bounded conversation/source/accepted-answer memory and
can wrap the single canonical job/publication state owner. Python owns analytical
contracts, policy functions, profiling, generated-query execution, targeted search,
and deterministic validation. Use one general SQL tool boundary with deterministic
schema/dialect/table/function/read-only/resource checks, not a fixed list of sales
answer tools. The engine must run in a proven compatible public runtime; no native
wheel compatibility is assumed.

The larger job DO/Workflow/R2/Container topology below is a future extension. For
small fixtures, decide compact evidence persistence and interrupted-job outcomes
without claiming resumable long-job execution. Keep one canonical owner when the
wrapper changes; do not add a parallel job store. The table distinguishes future
rows explicitly; general evidence, access, budgeting, and publication rules apply
in both slices. Each MVP cross-service request carries a versioned typed envelope: server-owned anonymous session scope, run ID, bundled source/snapshot IDs, plan version, operation ID, deadline, cancellation epoch, resource budget, and session-scoped artifact references. Authenticated principal/tenant fields belong to future private-workspace extensions. Recipients validate the envelope and authorization independently. External payloads use the repository's Pydantic boundary standard; internal values remain precise typed Python objects. Exact contract definitions belong in the architecture review.

**Documentation discrepancies:** Workflow limits currently list 50,000 Paid concurrent executions in the table while the waiting-instance explanation still says 10,000. Workflow script sizing says 3/10 MB while the Workers page reports 64 MiB. Do not build an MVP throughput/bundle claim around either discrepancy: verify target-account limits and deployable Python package size during FEXP-01/07. JavaScript streamed Workflow outputs are documented; Python parity is unverified. R2 references avoid dependence on that feature.

Python Workers run CPython compiled to WebAssembly through Pyodide, not ordinary Linux CPython. Pure-Python, PyEmscripten wheels and bundled Pyodide packages are supported; ordinary native Linux wheels are not generally interchangeable. The current package example uses Python >=3.13, satisfying the user's >=3.12 requirement. Pin a supported runtime and record `sys.version`, Pyodide/SDK versions and package ABI in the build artifact. Exact Pydantic/pydantic-core compatibility must be tested. Do not assume DuckDB, PyArrow or other native analytical wheels work there. Threading/multiprocessing are not a usable parallel-computation strategy, and the in-memory filesystem is ephemeral. [Python runtime](https://developers.cloudflare.com/workers/languages/python/how-python-workers-work/), [packages](https://developers.cloudflare.com/workers/languages/python/packages/), [standard library](https://developers.cloudflare.com/workers/languages/python/stdlib/).

CPython Containers provide the deliberate native-package boundary. New applications are directed to `ctx.container` and the `durable_object` scheduling policy; lifecycle control chooses immutable image/instance references. DO and Container are not guaranteed to share a location, and restarts can change placement. R2 FUSE is not local-SSD performance. Hence “computation close to data” is established for source-side PostgreSQL and a credible Basin design; it is an untested network/pruning proposition for Container-to-R2. [Container API](https://developers.cloudflare.com/containers/api/durable-object-container/), [scheduling](https://developers.cloudflare.com/containers/configuration/scheduling-policy/), [lifecycle](https://developers.cloudflare.com/containers/concepts/architecture/), [placement](https://developers.cloudflare.com/containers/concepts/placement/).

Disk is ephemeral by default, but current Containers support immutable filesystem snapshots under the DO scheduling policy. Snapshots exclude running memory/process state; documented size/retention caps are 20 GB/30 days. They may accelerate restart/cache restoration, but are not the sole evidence archive or a substitute for application checkpoints. [Snapshots](https://developers.cloudflare.com/containers/guides/snapshots/).

DuckDB is a candidate general SQL engine in a compatible CPython runtime because it provides SQL/Parquet operations without a database server. Its out-of-core execution has exceptions: multiple blocking operators, large holistic aggregates and certain aggregate types can exhaust memory. SQL can access filesystem/network/extensions, so a read-only SQL-looking plan is insufficient security. Restrict tables/functions/extensions/files/network at executor level; validate model-generated SQL against declared engine capabilities, authorized tables/functions, read-only rules, and resource budgets; do not replace the general query engine with fixed sales-answer operations. [DuckDB workload tuning](https://duckdb.org/docs/current/guides/performance/how_to_tune_workloads), [DuckDB security](https://duckdb.org/docs/current/operations_manual/securing_duckdb/overview).

## Durable execution and validated publication

The original architecture correctly separates technical retries from analytical replanning. Cloudflare provides durable steps and instance control; the application must supply the external-side-effect contract. A step may retry after a result was written but before its checkpoint was recorded. A Workflow does not atomically commit PostgreSQL, R2 and DO changes. [Workflow rules](https://developers.cloudflare.com/workflows/build/rules-of-workflows/), [Workflow API](https://developers.cloudflare.com/workflows/build/workers-api/).

Use an operation key containing anonymous session scope, run, source snapshot, plan version and unit ID; future private-workspace jobs can add tenant scope. Reserve/lease work, write immutable content-addressed output, and commit a single manifest entry under an expected version/fence. Reducers consume only one committed result per expected partition. Completion requires all expected IDs, no duplicate logical records, declared rejection counts, identical source snapshot, and validated aggregation algebra. Ratios use summed numerator/denominator; global distinct/median/join/window results need an exact supported algorithm or a labeled approximation with error contract. Partitioning alone does not establish correctness.

Set distinct attempt limits for transport/timeouts, resource failures and analytical replans. Permanent auth/schema/unsupported-operation errors fail or request clarification rather than technical retry. A replan cannot reset the overall deadline, token allowance, scan allowance or number of validation rounds. Retain a human-wait state where interpretation or spend needs approval. Default platform maximum retries are not an appropriate product budget.

Cancellation has two parts: prevent future dispatch/publication immediately using a cancellation epoch; stop in-flight execution best-effort with a measured hard-stop procedure. Container `exec` has no automatic timeout; a disconnected or retried call can leave a process running or launch it twice. Killing its parent need not kill descendants, and commands under the new scheduling policy retain root capabilities despite a supplied user ID. Use dedicated trusted job execution, process-group supervision or full instance destruction, and stale-epoch rejection of late writes. Do not execute arbitrary model-generated Python/shell in a shared tenant/secret-bearing Container. [Container API](https://developers.cloudflare.com/containers/api/durable-object-container/).

Agents durable fibers persist state, but restart does not preserve a running lambda. Recovery needs application hooks; default recovery can discard bookkeeping, with bounded recovery retention. For future long jobs, keep one durable scheduling/retry engine: Workflows. The application job authority still owns accepted lifecycle/work/publication state. The first MVP requires durable memory and reviewed interruption outcomes, without promising Workflow resumption. Use Agent fibers only for justified short interaction responsibilities, with tested recovery; do not create overlapping fiber and Workflow retry engines. [Agent durable execution](https://developers.cloudflare.com/agents/runtime/execution/durable-execution/), [Agents and Workflows](https://developers.cloudflare.com/agents/concepts/workflows/).

Stream progress, tool status and clarification while working. Keep candidate factual answers internal until Validator PASS; then publish the exact validated candidate hash. The native resumable chat stream must be tested against this publication gate: SDK defaults do not prove absence of an early unvalidated answer. A client reconnect reads authorized committed state rather than resubmitting execution. [HTTP/SSE](https://developers.cloudflare.com/agents/runtime/communication/http-sse/).

## Security, freshness, and operational ownership

Source content is untrusted data, including instructions embedded in JSONL/documents, column names and values. The model can propose allowlisted tools; infrastructure enforces anonymous session scope, bundled-source allowlists, and operation permissions and validates arguments. The SDK's tool, MCP and Code Mode features are capabilities, not application security policies. MVP needs no MCP server or model-generated JavaScript execution. [Agents tools](https://developers.cloudflare.com/agents/concepts/tools/).

Bindings reduce exposed endpoints but do not authorize an end user: Access context is not automatically propagated through service bindings. Carry server-owned anonymous session scope, resolve only bundled sources, derive internal resource IDs without trusting client-selected session paths, and deny cross-session history/job/evidence access. Authenticated membership/source grants are future private-workspace controls. Keep source credentials in environment-specific secrets; no secret values in plans, profiles, prompts, exceptions or traces. [Service bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/), [secrets](https://developers.cloudflare.com/workers/configuration/secrets/).

Hyperdrive query caching defaults to a 60-second freshness window plus 15-second stale-while-revalidate. Writes do not invalidate cached reads, and SQL comments do not control caching. Disable caching for freshness-sensitive billing and permission queries; pooling still helps. Define `as_of`, transaction snapshot availability, source watermark, schema fingerprint, freshness policy and mixed-version refusal. Source-side SQL on separate pooled sessions is not automatically one repeatable-read snapshot. [Hyperdrive caching](https://developers.cloudflare.com/hyperdrive/concepts/query-caching/).

R2 IAM changes can take up to a minute to propagate, and custom-domain caching can preserve obsolete/deleted content. Enforce application access revocation when issuing authorization or resolving opaque references; an artifact ID itself grants no access. Use direct private bindings for evidence. Lifecycle rules help retention but do not establish immediate erasure. Decide source snapshots, evidence, transcripts, model disclosure and deletion responsibilities before accepting sensitive data. [R2 consistency](https://developers.cloudflare.com/r2/reference/consistency/), [lifecycles](https://developers.cloudflare.com/r2/buckets/object-lifecycles/).

Workers AI with Llama 3.3 is the specified MVP baseline. Keep the adapter small and public; runtime/binding compatibility, structured output, tool behavior, analytical/validation quality, context fit, data handling, and measured usage/cost remain unverified until tested. External providers and alternative models are future options, not an open MVP selection. AI Gateway is optional if its routing/rate/analytics capabilities reduce work; it does not settle provider privacy. Any cache key includes anonymous session/access scope (tenant scope only for future private workspaces), source snapshot, semantics, prompt/model and plan versions. [Agent model integration](https://developers.cloudflare.com/agents/runtime/operations/using-ai-models/), [AI Gateway](https://developers.cloudflare.com/ai-gateway/).

Tracing is useful but requires content policy. `wrapAISDK` currently supports AI SDK v6/v7; direct SDK tracing does not capture payloads by default, whereas Flue tracing can include messages, tool arguments and results unless content capture is disabled. Python integration remains untested. Workers logs are sampled/truncated and have short retention (Paid up to seven days); keep complete provenance in R2. Instrument safe IDs, executor/image/model versions, retry class, coverage, scan bytes, peak memory/spill, token use and cancellation lag. [Agent tracing](https://developers.cloudflare.com/agents/runtime/operations/observability/tracing/), [Workers logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/).

Assume all other account usage is zero, eligible allowances unused, Standard storage and no optional search/catalog. These quantities stay within the compute/request/step/DO allowances. R2 storage is `(50−10)×$0.015 = $0.60`; baseline infrastructure is approximately **$5.60/month**.

Add a `standard-1` executor running ten hours/month: 40 GiB-hours RAM, 80 GB-hours disk and at most five active vCPU-hours. Excess RAM is `(40−25)×$0.009 = $0.135`; disk and CPU fit their allowances. Shared allowances and rounding can change the bill. No runtime or latency was measured to justify these assumed hours.

For a large scan illustration, 100 full scans of 2 TB compressed data are about 200 TB scanned: Basin SQL alone is approximately **$500/month** before the small allowance, R2/catalog/model costs and rounding. Pruning may greatly reduce this; unsupported/resource-heavy queries may fail. This is arithmetic from published rates, not evidence that this workload meets a latency SLO.

Track `total = shared Workers + Workflow steps/state + DO duration/storage/I/O + R2 storage/I/O + executor + Σ(model tokens × selected rates) + source/search/catalog/network`. A bounded model context does not imply bounded total inference: exhaustive semantic corpus work can cost partitions × model calls × tokens. Admission limits need scan, token, time, memory and spend ceilings. Estimate before dispatch; stop or request clarification when exhausted. Maintain per-tenant fairness and a global ceiling against source/model throttles. Application implementation remains Python >=3.12 using uv, Ruff, strict mypy, pytest, Radon and the repository's complete `make gate`. workflow services, credentials, or accounts. Live model and Cloudflare integration
tests use explicit credentials and a contributor's own authorized account.
172X authoring workflows must not become contributor or runtime prerequisites.
