## Screen/component responsibilities and activated states

No screens/components are activated. PROOF-1 is a textual diagnostic response: identity/status and limitations first, then actual SQL/exact typed cells, then source/hash/meaning, engine/Python/model versions and each Worker's runtime mode/build/version identity. Content labels below are UX-owned; wire schemas, codes and policies are architect-owned. Every `/proof/*` request requires operator bearer authorization; mutations also require exact same Origin. Outer Worker issues an HttpOnly server cookie and derives the session routing; no client-selected Agent or SDK/WebSocket state writes.
Mutation inputs use literal version `"1"`, extra-forbid types: source sales/support; query UUID request_id plus nonblank question ≤2,000 characters; `/sql` additionally SQL ≤8,000 bytes and strict max_rows 1–20; cancel owned job_id; reset owned state. Body cap is 16,384 bytes. Success returns SessionState: source/cancel/reset200; new query/sql202 immediately after durable queue; current duplicate active202/terminal200. Failure returns typed SafeError at its classified HTTP status. SessionState owns revision/source/capabilities/history/dropped_history/job/expires_at. ProofReceipt identifies proof_kind/ai_chain_complete/model_calls plus actual_sql, typed cells, source/hash/meaning and runtime/build versions; `analytical_validated:false` always applies. Integer results are canonical decimal strings/exact:true; REAL strings are exact:false without certified decimal error bound.
Provenance uses Python `runtime.runtime_mode/build_revision/worker_version_id` and separate `agent_runtime_mode/agent_build_revision/agent_worker_version_id`. Each deployed Worker UUID comes from its own CF_VERSION_METADATA.id; reviewed BUILD_REVISION is exact lowercase 40-hex committed build provenance. Missing/malformed deployed provenance fails closed. Explicit local mode permits truthful null IDs/unmanifested build and displays “Local runtime proof; deployed acceptance not established.” Provider deployment-object IDs are separate report evidence, never renamed Worker version IDs.
